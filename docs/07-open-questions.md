## Working assumptions (decided by us, revisit if contradicted)

- Manual upload of LG04 to DFØ by a human remains the process for the first runs.
- Import errors from Unit4/DFØ arrive as email to humans; no machine ingestion in MVP.
- Monthly cadence; the run cannot happen before the **6th of the following month** — Azure
  costs are final only 5 days in (DWH contact, 2026-07-08).
- Customer data reaches us from **CRM by import**, not by live reads (OQ-5); the local
  registry is a cache plus the offline/dry-run fallback. Until the interface exists, the
  registry UI is the only way to get customers into a run.
- Forsystem can validate kundenummer for **presence** (and, once decided, format). Unit4's
  LG04 import additionally marks kundenummer that are **unknown, wrong or deactivated** —
  detecting those here would require Unit4's customer list, which we do not have and have
  not asked for.
- The old system and this system share no infrastructure; the old PostgreSQL `difi`
  database is not read or written by forsystem.
